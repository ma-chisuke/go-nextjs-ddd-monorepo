# database

1 つの環境のデータベースを作るモジュールである。Aurora PostgreSQL のクラスターに、すべての区切られた文脈が共有する 1 つのデータベースを置く。あわせて、文脈ごとの 2 つのロールのシークレットと、デプロイのときにデータベースを準備する ECS のタスクを作る（TPL-0009、TPL-0016）。

| 部品 | 役割 |
|---|---|
| クラスター | データベースサブネットに置く Aurora PostgreSQL。アカウントの鍵で暗号化し、削除から保護し、自動バックアップを取る |
| クラスターのセキュリティグループ | ルールが名指すセキュリティグループからの PostgreSQL だけを受け付ける。そのルールは、各文脈が自分のタスクのために足す |
| ロールのシークレット | 文脈ごとの `<environment>/database/<context>/owner` と `<environment>/database/<context>/runtime`。値は、キー `username`、`password`、`url` を持つ JSON である |
| データベースを準備するタスク | デプロイのたびに、サービスが起動する前に `db/Dockerfile` のイメージを 1 回実行する |

## 容量

`capacity` は、容量の種類をちょうど 1 つ選ぶ。

- `serverless = { min_acu, max_acu, seconds_until_auto_pause }` は Aurora Serverless v2 である。既定は 0〜2 ACU である。最小が 0 なら、クラスターは接続のない状態が `seconds_until_auto_pause` 秒（既定は 300 秒）続くと一時停止し、使われていない環境はストレージの料金だけを払う。stg に向く。
- `provisioned = { instance_class }` は、`db.r8g.large` のような固定のクラスのインスタンスである。負荷が一定なら、Serverless v2 より安い。prd は負荷を見て選ぶ。

変数の検証は、2 種類を両方とも指定した値とどちらも指定しない値、最大より大きい最小、0.5 ACU 刻みから外れた容量、300〜86400 秒の範囲から外れた一時停止までの時間を拒否する。
`instance_count` で読み取り用のインスタンス（リーダー）を足せる。書き込み用のインスタンス（ライター）が故障すると、リーダーの 1 つが引き継ぐ。

クラスターが一時停止するのは、開いている接続が 1 つもないあいだだけである。そのため、クラスターに接続するものは TPL-0016 の規則に従う。

- サービスのコネクションプールは、使っていない接続を持ち続けない（`backend/internal/platform/postgres/pool.go`）。
- サービスのヘルスチェックは、データベースに触れない。
- RDS Proxy は、各インスタンスへの接続を開いたままにするので使わない。論理レプリケーションも使わない。
- 再開には約 15 秒かかり、1 日を超えて一時停止したあとは 30 秒以上かかる。接続はそれだけ待ち、失敗したらやり直す。サービスのプールは 30 秒待ち、データベースを準備するタスクは 5 回試す。

## 文脈によるデータベースの使い方

文脈のユニットは、このモジュールの出力から、そのサービスに次の 2 つを与える。

- 環境変数 `DATABASE_URL`。値は、実行時のロールのシークレットのキー `url` である。タスク定義に `valueFrom = "<runtime_secret_arns[context]>:url::"` と書き、実行ロールにはその ARN への `secretsmanager:GetSecretValue` を許可する。この URL は TLS で接続する（`sslmode=require`）。
- クラスターのセキュリティグループ（`security_group_id`）のインバウンドルール。自分のタスクのセキュリティグループからの、ポート 5432 への接続を許可する。

シークレットは、Secrets Manager がアカウントのために管理する鍵で暗号化される。そのため、シークレットを読めるロールに、鍵への権限は要らない。

## パスワード

ロールはパスワードでサインインする。パスワードは、ECS が Secrets Manager から読み、タスクの環境変数に入れる（TPL-0014）。IAM データベース認証は使わない。

- 各ロールのパスワードは、Terraform のステートに入らない。パスワードは、エフェメラルリソース `random_password` が実行のたびに作る。書き込み専用の引数 `secret_string_wo` は、`password_version` が変わったときだけ、そのパスワードを Secrets Manager に送る。パスワードは英字と数字だけからなるので、そのまま URL に入れられる。
- マスターユーザーのパスワードは、RDS が作り、専用のシークレットに保管し、ローテーションする（`manage_master_user_password`）。マスターユーザーとしてサインインするのは、データベースを準備するタスクだけである。
- ロールのパスワードをローテーションするには、`password_version` を上げて適用し、データベースを準備するタスクを実行してから、サービスを起動し直す。タスクを実行してから起動し直すまでのあいだ、サービスは古いパスワードを持っているので、新しい接続に失敗する。

## データベースを準備するタスク

`db/Dockerfile` のイメージは `db/prepare.sh` を実行する。このスクリプトは、まず再開の途中かもしれないクラスターを待つ。次に、マスターユーザーとして `db/bootstrap.sql` を実行し、各ロールのパスワードをそのシークレットから設定する。最後に、各文脈の `schema.sql` を、その文脈の所有者のロールとして pgschema で適用する（TPL-0010）。どの手順も、もう一度実行してよい。
デプロイは、サービスが起動する前に、出力 `db_task` を使って `aws ecs run-task` でこのタスクを 1 回実行する。起動タイプは Fargate、サブネットとセキュリティグループは `db_task` のものを使い、パブリックアドレスは付けない。そのあとタスクが停止するまで待ち、コンテナーが 0 で終了していなければ失敗とする。

- タスクは、ポート 5432 でクラスターに届き、AWS のサービスにはネットワークの VPC エンドポイントで届く。許可するのは、エンドポイントのセキュリティグループと Amazon S3 のプレフィックスリストへの HTTPS である。アドレス範囲を名指すルールはない。
- 実行ロールに許すのは、`db_image` のリポジトリからのプル、ロググループ `/<environment>/db` への書き込み、タスクが使うシークレットだけの読み取りである。タスクのロールには権限がない。
- ルートファイルシステムは読み取り専用である。スクリプトはファイルを書かない。
- Aurora のマスターユーザーはスーパーユーザーではない。データベースを所有し、ロールを作れるだけである。PostgreSQL 16 以降では、スキーマをロールに渡せるのはそのロールのメンバーだけである。そこで `db/bootstrap.sql` は、マスターユーザーが作った所有者のロールそれぞれに、マスターユーザーをメンバーとして加える。`make test-db-image` は、手元の環境の PostgreSQL で、そのようなロールとしてイメージを動かす。

## クラスターの削除

`deletion_protection` は既定で有効である。クラスターを意図して削除するときは、先にこれを無効にして適用する。
削除すると、最終スナップショット `<environment>-final` が残る。同じ名前のクラスターをもう一度削除しようとすると、このスナップショットを消すまで失敗する。
Secrets Manager は、削除したシークレットを 30 日間保持する。そのあいだは、同じ名前のシークレットを作れない。

## AWS で未確認の事項

このモジュールは、AWS Emulator にだけ適用した（TPL-0017）。エンジンのバージョンには、エミュレーターが知る最新の 17.9 を使った。エミュレーターはすべてのリソースを受け付けた。ただし、クラスターに独自のポートを割り当てるので、適用したあとの plan にはポートの変更が出る。
AWS についての次の事実は仮定であり、初めて適用するときに確かめる。

- Aurora PostgreSQL には 18.6 があり、その Serverless v2 は 18.3 から最小 0 ACU を受け付ける（TPL-0016 では、この点が未確認のままである）。
- Aurora PostgreSQL 18 のマスターユーザーは、CREATEROLE と CREATEDB を持ち、クラスターが作るデータベースを所有する。また、自分が作ったロールの ADMIN OPTION を持ち（PostgreSQL 16 以降は、ロールの作成者にこれを与える）、拡張機能 `btree_gist` をインストールできる。
- マスターユーザーのシークレットは、キー `username` と `password` を持つ。ロールは、KMS の鍵への権限なしに、このシークレットとこのモジュールのシークレットを読める。
- ECS は、`"<ARN>:<key>::"` と書けば、JSON のシークレットの 1 つのキーを 1 つの変数に入れる。RDS が管理するシークレットでも同じである。

`tests/` のテストは、AWS provider のモックに対してモジュールを plan する。AWS が計算する値をアサーションが必要とするところでは、そのモックに適用する。そのため、`make check-all` は AWS のアカウントなしでテストを実行する（`validate-terraform`）。

入力、出力、リソースの一覧は、terraform-docs がコードから[英語版](README.md)に書き出す。コードの中の説明は英語なので、一覧は英語版だけにある。
