# web

1 つの環境の Web フロントエンドを作るモジュールである。Next.js のサーバーを Fargate の ECS サービスとして動かし、インターネットから届くただ 1 つのロードバランサーの後ろに置く（TPL-0014）。

- ロードバランサーは公開サブネットに置き、TLS 1.2 以上の HTTPS で応える。80 番ポートは HTTPS へのリダイレクトだけを返す。
- タスクは非公開サブネットに置く。パブリック IP アドレスを持たず、ロードバランサーからのリクエストだけを受け付ける。
- サーバーは、Service Connect のクライアントとして、文脈の API を `http://facility:8080` のような名前で呼ぶ。宛先は `environment_variables` で渡すので、1 つのイメージがどの環境でも動く。
- モジュールは `domain_name` の証明書を発行し、ホストゾーンを通して検証する。`certificate_arn` に既存の証明書を書いたときは、発行しない。ドメイン名は、ロードバランサーに向ける。
- タスクロールにはポリシーがない。サーバーは AWS のサービスを呼ばず、シークレットも持たないからである。
- ロードバランサーとコンテナのヘルスチェック `/healthz` は、API を呼ばない。そのため、文脈が止まっていても、サイトは止まらない。

## ただ 1 つの公開の入口

インターネットから届くものを作るのは、このモジュールだけである。
Trivy は、インターネットに面したロードバランサーを指摘する（`AWS-0053`）。[.trivyignore.yaml](../../../.trivyignore.yaml) は、この指摘を `infra/modules/web/main.tf` に限って認めている。
ほかのファイルに書いた公開のロードバランサーは、引き続き `make check` を失敗させる。

## AWS にはまだ適用していない

`make check-all` は、このモジュールを AWS Emulator に適用する。そのときの証明書は、リハーサルが自分でリクエストしたものである。エミュレーターは証明書を発行しないからである。既定の経路、つまり DNS の検証のあとに ACM が発行する証明書は、`tests/` のテストだけが、AWS provider のモックに対して確かめる。

このモジュールは、ロードバランサーのアクセスログを残さない。ログのバケットは、Amazon S3 が管理するキーで暗号化することになる。ロードバランサーが書き込めるのは、その種類のバケットだけである。一方、Trivy はバケットにカスタマーマネージドキーを求める（`AWS-0132`）。ログを足すときに、ログの扱いとこの指摘の扱いを決める。

入力、出力、リソースの一覧は、terraform-docs がコードから[英語版](README.md)に書き出す。コードの中の説明は英語なので、一覧は英語版だけにある。
