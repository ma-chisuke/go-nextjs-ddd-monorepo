# registry

1 つの環境が動かすイメージの Amazon ECR リポジトリを作るモジュールである。各文脈のイメージや Web フロントエンドのイメージなど、イメージごとにリポジトリを 1 つ作る（TPL-0014）。

- タグは変更できない。1 つのタグはずっと同じ 1 つのイメージを指す。そのため、タグを指定したタスク定義はレビューを通ったイメージを動かし、プッシュによってロールバック先が変わることもない。
- ECR は、プッシュされたイメージをそのつどスキャンする。
- ライフサイクルポリシーは、各リポジトリで、タグの有無を問わず新しいほうから `kept_images` 個（既定は 30 個）のイメージを残し、残りを期限切れにする。タスク定義がまだ指しているイメージも期限切れになりうる。そうなるとそのサービスはタスクを起動できないので、ロールバックに要る数より多くのイメージを残す。

文脈のサービスがプルできるのは、自分のイメージのリポジトリだけである。モジュール [context-service](../context-service/README.md) は、そのリポジトリの ARN を `repository_arns` から受け取る。

`tests/` のテストは、AWS provider のモックに対してモジュールを plan する。そのため、`make check-all` は AWS のアカウントなしでテストを実行する（`validate-terraform`）。

入力、出力、リソースの一覧は、terraform-docs がコードから[英語版](README.md)に書き出す。コードの中の説明は英語なので、一覧は英語版だけにある。
